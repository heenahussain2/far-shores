Planetary Travel Guide

APPROVED

React + TypeScript + Vite. Plain CSS. Your catalogue, saved in this browser.

Companion to the canonical technical specification. Expand components to connect PRD behaviors to implementation files. The reference-distance proposal was accepted with the plan.

How this works

The app loads eight bundled profiles or your saved catalogue. React renders the cards and profiles; TypeScript keeps the record shape consistent. Editing creates a separate draft. Saving writes the catalogue successfully before the interface reports success.

Booking combines a calculated journey estimate with stored packing advice and deadpan survival copy. Unknown details stay unknown. No live API, account, or real reservation is involved.

Seed data / browser storage ↔ repository ↔ React views. Profile and reveal share one calculator. A future backend replaces the storage adapter; migration and account decisions remain future work.

Approved reference convention

What does “approximate distance” mean?

Accepted at review: use the rounded difference between Earth's and each planet's approximate mean orbital radii, based on NASA/JPL data. It is a clearly labelled orbital-radius-gap example, not current separation or a time average.

Earth is zero: a local staycation. Distances remain editable. Every estimate carries the movement note and explicitly states its simplified constant-speed assumption.

Agreed calculation: distance ÷ cruising speed. Default speed: a fictional 100,000 km/h, editable per planet. Unknown distance or speed means unknown travel time.

Component map

01 / App shell and catalogue

App.tsx, LandingCover.tsx, DestinationCatalogue.tsx, PlanetCard.tsx

Implements PRD → The Core Journey and Browse and Search. Hash routes select the home cover (#/), separate catalogue (#/destinations), or a stable planet ID, with browser Back and refresh support. Keyed pages use a short CSS fade-and-slide entrance; reduced motion disables it and the shared header/footer remain stable. Search is trimmed, case-insensitive, and matches partial names. No-match results provide clear-search; unknown IDs provide a return action.

One catalogue in React memory; no router or global-state library. New entries use UUIDs, so duplicate or changed names do not overwrite another record.

02 / Profile and imagery

PlanetProfile.tsx, PlanetImage.tsx

Implements PRD → Read Planet Profiles. Image/name/introduction → scientific details → atmosphere → artistic living-there interpretation → booking. Show units, speed assumptions, and the movement note.

Bundle initial imagery with credits. Users paste HTTP(S) image URLs; blank or unavailable imagery uses a neutral placeholder. Optional missing information displays Unknown.

03 / Entry form and validation

PlanetForm.tsx, validation.ts

Implements PRD → Add and Edit Planets. Name and description are required. All planet information remains editable; journey time updates from distance and speed inputs.

Blank optional numbers become null. Supplied distances must be finite and nonnegative; speed must be finite and positive. Validate pasted image URL schemes. Save writes before reporting success; Cancel discards the draft. Validation or saving errors retain the user's input.

04 / Holiday reveal and shared calculation

HolidayReveal.tsx, journey.ts

Implements PRD → Book and Reveal the Holiday Verdict. A single reveal shows “Travel booked!”, fictional-trip label, calculated time, packing advice, and deadpan survival label/sentence. Repeat clicks do not add duplicates.

Missing a valid time, packing advice, or either survival field triggers the booking-button risk icon/text and “Details unknown. Book at your own risk.” Known details remain visible. The icon signals missing information, not physical safety.

Estimate, formatting, and risk checks share one utility. Preserve zero journey time as known; do not store a second independent estimate.

05 / Storage boundary and failure handling

catalogueRepository.ts, localCatalogueRepository.ts, useCatalogue.ts

load(): Promise<Planet[]>
save(planets: Planet[]): Promise<void>

Implements PRD → Add and Edit Planets and States and Boundaries. Store the full versioned catalogue snapshot under planetary-travel-guide.catalogue.v1. Seed only when storage is absent; never append seeds on every refresh.

Validate loaded data. Corrupt or unsupported data remains untouched, with an error and read-only seed browsing. Failed writes retain the draft and previous saved view; retry is available.

Backend question resolved: UI components depend on this interface rather than calling localStorage. A future API adapter can replace it, but migration, server storage, and authentication still need design.

06 / Planet record and content

types/planet.ts, data/planets.ts, CONTENT_SOURCES.md

  • Stable ID, required name and description.
  • Image reference; Earth-distance reference and its basis; distance from Sun/host star; assumed cruising speed.
  • Atmosphere, artistic living-there text, packing advice, survival label/sentence.

Optional values may be null. Journey time and risk are derived; temporary search, draft, and reveal state are not persisted.

Prepare eight complete seed records. Verify individual facts and images with NASA planet profiles, JPL orbital elements, and NASA media guidance. Record source links, reference-distance calculations, and image credits. These are build-time sources, not runtime API dependencies.
