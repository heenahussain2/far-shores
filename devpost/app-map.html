FAR SHORES / REFERENCE GUIDE

Your app, mapped.

A planetary travel guide: browse eight initial worlds, maintain your own catalogue, and create a fictional travel pass. React renders the screens; shared utilities validate records and calculate journey estimates. Browser storage keeps saved additions and edits at the same origin.

Follow one action: Save destination

1. Form →PlanetForm validates the draft before calling onSave.
2. Store →App passes it to useCatalogue; the repository writes the full snapshot.
3. ProfileOnly after saving succeeds does the catalogue update and the profile appear.

A three-stop reference route

This is a reference route, not a record of an interactive code tour.

  1. src/components/PlanetForm.tsx — find submit. Required fields and invalid values are checked with validateDraft; a failed save leaves the draft available. Both Cancel buttons use the same callback.
  2. src/App.tsx — find savePlanet and cancelForm. A successful save opens the destination and clears stale booking data. Cancel exits without saving and restores focus.
  3. src/hooks/useCatalogue.ts — find save. It awaits repository saving before updating React state. localCatalogueRepository.ts validates the snapshot and writes localStorage; failures are reported without claiming success.

To change this, start here

  • Cover and catalogue: src/components/LandingCover.tsx, DestinationCatalogue.tsx, and src/styles.css.
  • Profile sections and scrolling: src/components/PlanetProfile.tsx, find goToSection and profile-details.
  • Initial facts and sights: src/data/planets.ts, src/data/sights.ts; keep factual credits in CONTENT_SOURCES.md updated.
  • Journey calculations and missing-details warning: src/lib/journey.ts and journey.test.ts.
  • Booking and closing: src/App.tsx, find bookTrip and closePass. Ticket display: src/components/TravelPass.tsx. Download content: src/lib/travelPass.ts and its tests.

A practice to reuse

Turn feedback into a visible acceptance condition. “Discover skips the top” became “focus and scroll to the beginning of the details, above the scientific information.” The requirement is recorded in devpost/prd.md under Read Planet Profiles and implemented by goToSection in PlanetProfile. Browser verification checked the landing position and keyboard focus at desktop and phone widths. For a future project, define what should become visible and focused before asking an agent to revise navigation.

Run and verify

From the repository folder, use Node.js 24 and run npm ci, then npm run dev. Open localhost:5173. Run npm run test and npm run build for the automated checks. Saving is per browser and origin; booking is temporary, while downloaded HTML passes can be kept.
